## Context / why this iteration

patches **A: lane-depart-brake** and **B: recovery-reverse-out**. The user observed lane-centering "kept

## Part 1 — Behavioral fixes (priority order)

**P1 — Upcoming-curve SPEED GOVERNOR that works on a 2-point path (THE catastrophe fix, #1/#2/#3).**
The curve-brake measures the bend only when `pathPolyline.Count ≥ 3` (`ComputeCurveBrake` `:21161`) — but
approaching a node the path is often 2 points, and the *next link's* heading is what defines the turn.
Add a governor that brakes proactively when the path is degenerate (≤2 pts) AND the node-graph link angle
at the lead node (or heading-delta to the node-after-next) exceeds ~45–60°, scaled by speed and
distance-to-node. The node graph is already queried for offsets (`NodeGraph.FindNearestNode`/`GetLink`,
~`:20501-20518`) — reuse it. This is the single highest-value change: it prevents the airborne launch that
no downstream brake can recover. Native calls: node-graph reads already in use (DSH 3.6+ safe).

**P2 — Keep the assist + brake live when the path collapses at speed (the F1364 dead window in #1).**
At the collapse, `steeringAssistActive=false` (`:11261`) zeroed `brakeArmed` and skipped the whole brake
path for ~5 frames at 33 m/s. Extend the activation gate (`:11250`) to stay active whenever
`vehicleSpeed > ~15 m/s` even with a degenerate path / `roadSteerCorrection≈0`, so curve/skew brake and
the `laneCollapseAtSpeedTicks` floor (`:21143`) actually run. A fast car with no forward guidance must
brake, not coast.

**P3 — Cap re-acceleration while off-road or skewed during/after recovery (#3's 2nd impact).** After the
#1 crash, recovery exited to LaneKeeping and the car re-accelerated 3→24 m/s while still off-road, driving
into impact #2. Add a hard speed ceiling (throttle lock / brake floor) whenever `!IsPositionOnRoad(pos) ||
|vehicleSkewAngle| > ~30°`, released only once realigned on-road. Sites: recovery→LaneKeeping handoff
`~:10720-10748` and the throttle apply path `~:13911`.

**P5 — Arm stuck-recovery under a threat-brake hold (#4/#5/#6 wedge family; recurring iter-28 P1 gap).**
When the car is stopped/creeping off-road or against a static prop while the threat-brake holds it
(`own=ramped/handbrake`, `stuckLayer=0`), stuck-recovery never escalates. Add: if `speed < ~1 m/s` for
>~2 s AND a static obstacle sits within ~3 m AND (`|lat|` large OR `!IsPositionOnRoad`), force-arm
recovery/reverse instead of letting the threat-brake pin it indefinitely. Scope tightly (stopped +
off-road/obstacle + sustained) so rural-dirt false-ejects don't return.

**P4 — Give the Stanley controller more low-speed authority for large sustained errors (#8/#9).**
`STANLEY_CROSS_MAX_RAD=0.35` + `STANLEY_CTE_CAP_M=4.0` saturate at 5 m / 5–6 m/s, yet the car stays
"on road" so recovery never arms. Either (a) **scale the cross cap up as speed drops** (a slow car can
safely use more steering angle) at the clamp `:20947`, or (b) arm a gentle realignment when `|lat| > ~4.5 m`
is sustained on-road >~1.5 s at low speed. Also let iter-29 A fire on a *sustained* (not only *growing*)
large error — its gate `ldRate > 0.5` (`:10296`) misses steady drift.

**P6 — Revert lane-centering to dark-launch until the signed model lands (iter-28 decision, was
overridden).** The offset is a **fixed half-lane-width to the driver's RIGHT** whenever the road is two-way
(`if (bwd > 0) offMag = LANE_WIDTH_M * 0.5f`, `:20520`; right-perp `:20494`; applied `:20547`) — wrong-signed
whenever the car is already right-of-center or should bias left, and 0 on divided roads. It did not *cause*
the failures but adds an uncorrected right bias the iter-28 plan (lines 57–61) explicitly said to defer.
Set `laneOffsetPolyline` back OFF (in-game toggle, or the menu default) until a **signed per-side** offset
(push toward the correct lane, not always right) is implemented. Keep the `poly-offset` calibration line
emitting (it still computes when OFF — dark-launch, `:20546` gate).

**Reverse-out (iter-29 B) refinement (supports P3/P5):** gate it so it fires only when the rear points
back toward the road — require `|skew| < ~25°` so "straight back" reduces `lat` rather than increasing it
(it drove −27 → −36 at skew ~50° in #3). Site `~:10761-68`.

## Part 2 — Debug / logging fixes (behavior-neutral; the user asks for these every iteration)

Ordered by value. NOTE the synthesis reconciliation: **`ctrlB` readback is a known artifact** — control 72
is DISABLED (`:13777`) before the simulated write, so `GET_CONTROL_NORMAL(0,72)` reads 0 even at
`rampedBrake=1.0`. Log the **commanded** brake + `decelMs2` + `wheelsDown`, NOT `ctrlB`.

1. **Un-gate the auto-collision detector from `!IsInAir` (`GTA11Y.cs:4930`) — TOP fix.** Airborne tumbles
   (the worst crashes) are silently dropped: F1495 bodyDrop=111 and F2506 bodyDrop=158 had **no
   AUTO-COLLISION marker**, and the in-air `else` (`:4984-89`) resets the health baseline so the
   first post-landing frame is skipped too. Run the body/engine-delta comparison regardless of air state
   (the `speed > 1.5f` + body/engine thresholds already prevent false positives) and annotate the marker
   `airborne=true`. Illuminates #1/#2/#3.
2. **Emit `EVENT collision-suppressed`** (throttled) + a running `suppressedCollisionCount` when a real
   body/engine drop is rejected by the 1 s cooldown or threshold (`~:4967-77`). Today a deduped/thresholded
   impact leaves zero trace — we can't tell "no collision" from "collision swallowed."
3. **Enrich the failClass snapshot** (`:20134-20146`) with the fields that were stale/absent exactly when
   needed: add `decelMs2`, `wheelsDown`, **commanded brake** (`cachedBrakeMagnitude`/`rampedBrake`) and
   `armed`; `offRoadDurMs` (from `offRoadStartTicks`, already in the FRAME line `~:19675`, far better-armed
   than `lowOffRoadMs`); `latAgeMs` (FRAME `~:19671`) to flag stale node-snaps; `laneDepartStreak` +
   `laneDepartBrakeActive` (iter-29 A — currently invisible at the failures); and the lane-offset
   explainers `fwd/bwd/jblend/src` (cached `lastLaneOffset*`, `:20541-43`) so `offsetWouldBe=0.00` is
   interpretable. **Re-source or drop `recentWedgeMs`** — it is −1 at all 9 failures (only arms at
   `stuckLayer≥1`); reuse `lowSpeedAnyStartTicks` like iter-29 C6's `wedgeMs`.
4. **Gate `LANE-OFFSET` on `nativeOnRoad`** (`:20127-20130`). #9 (`nativeOnRoad=False`, lat 5.4, spd 5.9)
   was an off-road drift mislabeled LANE-OFFSET only because `|lat| 5.4 < 8` and `spd 5.9 > 5`. Require
   `fcNativeOnRoad` for LANE-OFFSET so off-road events at lat 5–8 m read LATERAL-OFFROAD.
5. **Add control outputs to the lookback ring** (`DriveScalar` struct `:95-99`; emit `:20183-86`): add
   `steerCmd` (`cachedSteerCorrection`), `brakeCmd` (`cachedBrakeMagnitude`), `decelMs2`, `wheelsDown`.
   The ring is fresh at all 9 failures but carries no control signal, so we can't see whether the
   controller was fighting the drift and losing during the #1/#2/#3 run-ups.
