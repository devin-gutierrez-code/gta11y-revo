**Source sessions:** driveassist-2026-07-04-062742 (iter35, 16.5 min, 47 markers / 32 incidents, 2.85 fails/min) and driveassist-2026-07-04-090210 (iter35, 1.1 min, 5 markers / 2 incidents, 4.59 fails/min). Two vehicle deaths across the pair.

## 1. Executive summary

Iter35 failed because every safety system is individually gated by preconditions that the two dominant kill scenarios don't satisfy: a stationary, aligned, hands-off car being ground by an NPC arms *no* stuck path (skew too low for `offLaneOrSkewed`, throttle zero for `squareOnStall`, and no latched brake flag for `threatBrakePin` — GTA11Y.cs:13117-13163), while the wedge-damage handler actively handbrake-pins the car in the kill zone (15246-15268) waiting for an escalation that never comes; and the monotonic-TTC filter structurally rejects constant-TTC standoff attackers (one gate, two kill paths, both vehicle deaths). Iter36's strategy is **not** more tweaks: it is four systemic changes — (a) damage becomes a first-class arming/corroboration signal everywhere, (b) escape mechanisms must never veto themselves (inch-back self-cancel, grind-vetoes-reverse), (c) the ladder/locus clock must be un-starvable, (d) the keep-alive gate must never sleep while distressed — plus the P0 logging fixes so the next session is diagnosable per-incident.

Iter36 deliberately ships fewer, deeper patches.

## 2. Behavior fixes (priority order)

### B1 — Damage-grind arm + wedge-handler demotion (kills death #1 mechanism)

**Root pattern (verified).** All three arm gates at 13117-13163 fail simultaneously for "stationary, aligned, on-road, ground by NPC": skew 2-6° vs `NOPROGRESS_SKEW_ANGLE`=35° (1098); throttle 0 vs the 0.25 `squareOnStall` gate (13148); and `threatBrakePin` (13156-13162) — which already contains a damage-corroboration term (`lastBodyDropTicks` within `STUCK_OFFROAD_TICKS`=3 s, 13159) — is dead because its `assistBrakeHold` precondition needs `brakeArmed || emergencyBrakeActive || cachedHandbrakeMagnitude > 0.1f`, and the wedge-damage handler at 15248 writes control 76 raw without touching `cachedHandbrakeMagnitude` (whose only setters are 11950/13759/14120/14291/15019). `RECOVERY_GIVEUP_DAMAGE_TICKS` (1211) is dead code in this scenario because recovery never engages.

**Design decision — one arming authority, not three overlapping fixes:**
1. New fourth arm path in `UpdateStuckRecovery` after 13162: `bool damageGrindArm = lastBodyDropTicks > 0 && (now - lastBodyDropTicks) < STUCK_OFFROAD_TICKS && speed < STUCK_SPEED_THRESHOLD;` then `armEligible |= damageGrindArm`. (Reuse `STUCK_OFFROAD_TICKS` = 30000000L = 3 s DateTime ticks, line 124 — the same window `pinCorroborated` already uses at 13159; do not mint a new literal.) When `damageGrindArm` is the only true gate, use `NOPROGRESS_DETECT_TICKS/3` (~1 s; base is 30000000L at 1096). Extend the `stuck-arm` event's `arming=` vocabulary (13450-13451) with `damage-grind`.
2. Demote the wedge-damage handler (15246-15268): condition the control-76 pin on `stuckLayer == 0 && !alignmentEngageReverse && !pivotEscapeActive` — once recovery arms, the pin must yield. Change the spoken cue from "Stuck and taking damage. Backing out." (15266) to "Stuck and taking damage." (at layer 0 nothing is backing out yet — the current phrase is untrue at the moment it plays). Complementary one-liner while pinning: also set `cachedHandbrakeMagnitude = 1f` so the existing `threatBrakePin` gate (13156) lights up as designed; clear it when the pin releases (mirror the 15019 pattern).
3. Grind must not veto its own escape: `grindingNow` (damage < 800 ms old — `WEDGE_DAMAGE_RECENT_TICKS` = 8000000L at 1183) unconditionally forces `reverseEmergency` at 15072-15090, which aborts the reverse (`alignmentEngageReverse = false`, 15125) → during an active NPC grind, layer-2 reverse is permanently vetoed. Fix: record `reverseStartTicks` when `alignmentEngageReverse` first engages; `grindingNow` contributes to `reverseEmergency` only if `lastBodyDropTicks > reverseStartTicks + 3000000L` (300 ms settle — damage newly incurred *while reversing*). `rearHardStop` and `emergencyBehind` remain unconditional.
4. Dead-vehicle latch: on vehicle death (`curBody <= 0f && curEngine <= 0f` — the `vehDeadNow` predicate at 5380 — or `Vehicle.IsDead`) suspend the assist and announce "Vehicle destroyed. Assist off."

**Expected effect:** death-#1-class incidents become grind detected ≤1 s → arm → reverse executes → the `RECOVERY_GIVEUP_DAMAGE_TICKS` fast path is finally reachable. **Risk:** false arms in fender-benders — mitigated (layer 1 is a wait; `speed < STUCK_SPEED_THRESHOLD` required); gate behind `stuckDamageArm=1`.

### B2 — Standoff threat class: proximity + closing-velocity bypass of the monotonic filter (kills death #2 mechanism)

**Root pattern (verified).** `BRAKE_MONOTONIC_FRAMES = 3` (723) is consumed in `BrakeThreatPassesEntityGates` (9445-9555): the streak increments only on a per-sample TTC *drop* ≥0.04 s (9529-9537) — a head-on pusher holding constant gap never accumulates a streak (entity 357994 rejected ~40 s with `monotonic-streak count=0` until the 980-pt kill, Dorset, F41523). The two existing bypasses don't cover it either: the high-speed bypass (9476) needs own speed > 8 m/s, and the `EMERGENCY_BRAKE_TTC` bypass (9501) needs a valid TTC < 0.4 s, which a zero-closing-rate standoff never produces. The same unarmed state keeps `threatBrakePin` dead — one filter, two kill paths.

**Mechanism:** add a third bypass in `BrakeThreatPassesEntityGates` (pattern-match the two existing ones at 9476 and 9501), arming independently of monotonicity when ALL of: entity dist < 6 m ahead (dot with `ForwardVector` > 0), own speed < 2 m/s, entity velocity component toward player > 0.5 m/s (`Entity.Velocity`). The function currently receives only `handle`/`ttc`/speeds — resolve the entity via `Entity.FromHandle(handle)` inside the bypass (or plumb position/velocity from the callers at 9796/9843/10290/10380/10452). On bypass: set the streak to `BRAKE_MONOTONIC_FRAMES` (as the existing bypasses do at 9483/9506), let `brakeArmed` latch, refresh `cachedBrakeThreatPos` (this makes `blockedAhead` at 13128-13134, `freshCloseObstacle`/`strandedHold` at 4994-5008, and `threatBrakePin` live), and emit `EVENT brake-standoff: ent= dist= closing= ownSpd=`. Doesn't touch the monotonic normal path (ACC at speed unchanged). Complementary to B1: B2 makes the threat visible *before* damage lands; B1 catches whatever still lands. **Risk:** brake-arm vs harmless creeping traffic — bounded (requires them moving into you while you are stopped); gate behind `standoffThreat=1`.

### B3 — Ladder & locus-clock integrity

**Root pattern (verified).**
(a) Freed exit at 13332 fires on the bare `!stillStuck` disjunct (`stillStuck = inRecovery || noProgressArm || pivotEscapeActive`, 13331) — a momentary mode-flip plus a >3 m twitch (which resets `noProgressSinceTicks` at 13173-13177) collapses the ladder to 0 long before `STUCK_FREED_DISTANCE` = 8 m.
(b) Locus time accrues only while `stuckLayer >= 1`: the `stuckLayer == 0` branch returns at 13474 before the accrual block at 13480-13486 → session max cumMs 5,253 vs the 45,000 needed; layers 3/4 unreachable via the locus clock.
(c) Flip-cycle giveup fired `flips=4 heldMs=0`: the flip counter (13226-13237) counts every mode change with no minimum hold, and `flipCycle` (13261-13262) has no time floor — `heldMs` in the giveup line is the no-progress clock, which can legitimately be 0 when the giveup is flip-triggered.

**Mechanism:**
1. Freed exit (13332): replace the bare `!stillStuck` disjunct with `(!stillStuck && speed > 3f && PlanarDist(playerVeh.Position, stuckPosition) > 4f)`. `movedClear` (8 m) and `alignedNow` unchanged.
2. Locus accrual decoupled from the layer: accrue whenever `stuckLocusValid && PlanarDist < STUCK_LOCUS_RADIUS && speed < STUCK_SPEED_THRESHOLD && distressed`, where `distressed = stuckLayer >= 1 || armEligible || reverseAbortDeadlockUntilTicks > now || (now - lastBodyDropTicks) < STUCK_OFFROAD_TICKS`. Preserve the existing accrual-gap property (only add `now - stuckLocusLastAccrualTicks` when < 2 s, 13482-13484) and keep the 10 s fast-driving clear (13461-13472).
3. Thresholds (1055-1056): `STUCK_LOCUS_AUTODRIVE_TICKS` 450000000L (45 s) → 300000000L (30 s); `STUCK_LOCUS_TELEPORT_TICKS` 750000000L (75 s) → 600000000L (60 s).
4. Flip-cycle giveup: add a time floor to the trigger — `flipCycle` additionally requires `recoveryGiveupSinceTicks != 0 && (now - recoveryGiveupSinceTicks) >= 15000000L` (1.5 s of engaged recovery), so a giveup can never fire with `heldMs=0` before recovery has actually tried anything.

**Expected:** the dead-air cluster (incidents 28-32) and (-1634,-978)-class wedges hit layer 3 by ~30 s worst case. **Risk:** more autodrive/teleport takeovers — acceptable per the escalation design; constants trivially reverted.

### B4 — Reverse-escape viability: signed-speed inch-back, stationary-entity margin, slope-aware rear probe

**Root pattern (verified, 15070-15158).**
(i) `inchBack` requires `playerVeh.Speed < 1.0f` (15088) but then commands `ForwardSpeed = -1.2f` (15147); `Vehicle.Speed` is an unsigned magnitude, so the successful creep immediately disqualifies its own gate → abort/inch oscillation → abort-deadlock (090210 F950).
(ii) `REVERSE_ENTITY_ABORT_MARGIN` = 3.0f (1182) ignores rear-entity velocity — a parked car at ~4 m real gap blocks every escape.
(iii) The rear probe (4724-4748) casts a *planar* `behindDir` (Z zeroed, 4726) with `IntersectFlags.Map` from `startPos = playerPos + 0.5 m Z` (4605) — uphill terrain reads as a wall; the shape-cast's `hitNorm` out-param is captured and discarded (4730-4737), so there is no slope information at the abort decision (`rearType=world` aborts at 2.4-4.0 m).

**Mechanism:**
1. Signed gate: replace the `playerVeh.Speed < 1.0f` term at 15088 with `Vector3.Dot(playerVeh.Velocity, playerVeh.ForwardVector) > -1.5f` (still inching or slow; only a reverse already faster than 1.5 m/s exits the branch).
2. Stationary-entity margin: if the rear entity's speed < 0.5 m/s, use `rearHardStop + 0.5f` as the abort floor instead of `rearClearNeeded + REVERSE_ENTITY_ABORT_MARGIN`; moving entities keep the full margin. Entity identity: `PerformShapeCast` already retrieves `oHitEnt` from GET_SHAPE_TEST_RESULT (15707, 15722) and throws it away — plumb it out; fallback `World.GetNearbyVehicles` near the rear hit position.
3. Slope filter: keep `hitNorm` in the rear consumer; if `hitNorm.Z > 0.7f` classify the hit as ground, ignore it as a rear blocker, and log it; raise the rear-cast origin from the current center+0.5 m to bumper height + 0.4 m.

Interaction with B1(3): together they convert the abort-deadlock net-action-zero into an actual crawl-out; the abort-standoff deadlock counter (15093-15116) stays as backstop. **Risk:** backing into unseen low geometry — bounded by the untouched hard floor (`REVERSE_REAR_HARD_STOP`, re-checked every frame) — gate items 2 & 3 behind `reverseRearV2=1`.

### B5 — Keep-alive: no sleep while distressed + sub-bumper wedge visibility

**Root pattern (verified).** The gate at 5011-5023 stops `ProcessSteeringAssist` AND `UpdateStuckRecovery` when speed < 2 in LaneKeeping with no brake/grace/stranded-hold; `strandedHold` needs a cached obstacle (4994-4996) which the below-bumper static rejector (10159-10164; `belowBumper=154/154`) structurally denies → 40+ s dead air (incidents 28-32) off-road at lat = -9 m.

**Mechanism:**
1. Add keep-alive terms to the disjunction at 5011: `|| offRoadStartTicks > 0 || Math.Abs(lastLaneLateralError) > 4f || (lastBodyDropTicks > 0 && DateTime.Now.Ticks - lastBodyDropTicks < 50000000L)` (5 s).
2. Low-obstacle corroboration cache: in the static-reject path (10159-10164), when `rejReason == "below-bumper"` AND dist < 4 m AND own speed < 2 m/s, store new fields `cachedLowObstaclePos`/`cachedLowObstacleStamp`. Consume ONLY in `blockedAhead` (13128-13134) and `freshCloseObstacle` (4994) — never in the ACC/brake path (do not regress the iter-29 ground-graze fix). Log rejected-hit relZ samples.

**Risk:** low; reuse the `stuckDamageArm` gate for the damage term.

### B6 — Lane-model stabilization (targeted mitigations only)

**Root pattern:** lat-snaps 5-10 m, junction tangent sign-flips (+72.7 → -62.5 in one frame), frozen poly-hold (lat locked -5.30/-9.08 for tens of seconds), resume-on-stale-scan (2575 ms) → Joshua Rd grinds, resume-into-wall -53.4, wrong-way turn (jIdx=73 violFrames=259) feeding death #2.

**Ship:**
1. Lat-snap clamp: if |Δlat| > 5 m while planar displacement < 2 m, hold the previous lat, mark `latStale`, cap steering authority to 30% until 3 consecutive consistent frames; `EVENT lat-snap-clamp`.
2. Junction tangent hysteresis: refuse a tangent > 45° from the held tangent unless 2 consecutive frames agree.
3. Stale-scan resume guard: assist-resume `reason=speed` requires a scan < 1000 ms old; force a fresh scan cycle before authority resumes.
4. Wrongway-junction instrumentation only (`EVENT wrongway-junction: jIdx= violFrames= heading= tangent=`); poly-hold expiry (invalidate + rescan if lat is bit-identical > 5 s while moving).

All behind `laneStability=1`.
