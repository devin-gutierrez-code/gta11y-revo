## H1 (P0) — Transient-blocker-aware stuck ladder (`UpdateStuckRecovery`, Layer-1 entry ~:11800)

Before entering Layer 1 from an arm, classify the blockage using EXISTING caches (zero new World
queries): `navAssistPedCenter`/`navAssistVehicleCenter` (live refs + `.Velocity`), `threatType`,
`closestBrakeObstacleType`. If dynamic (ped/vehicle present or threat typed so): enter a WAIT
state instead of reverse — hold (existing brake machinery already holds), speak "Waiting for
traffic." (10 s cooldown), `EVENT stuck-wait: peds= vehs= moving= brakeType= waitMs= staticMs=`
every 2 s; escalate to the normal Layer-1 path only when the blocker has been static
`STUCK_WAIT_STATIC_TICKS=9 s`, OR `STUCK_WAIT_MAX_TICKS=25 s` hard cap, OR the blocker disappears
(next pass falls through naturally) — `EVENT stuck-wait-escalate: reason=static|timeout`.
New consts also: `STUCK_WAIT_BLOCKER_SPEED=0.4`. Reset `stuckWaitSinceTicks`/`stuckWaitLastDynamicTicks`
in the `else { stuckSinceTicks = 0; }` branch and in `ResetStuckRecovery()`.
**H1b:** the player-intent-only displacement arm path gets a longer window — at the window check
(~:11743): `assistCommanding ? STUCK_DISP_WINDOW_TICKS : STUCK_DISP_WINDOW_PLAYER_TICKS (10 s)`.
Static-geometry blocks keep the current immediate reverse. No interaction with grace-cancel
(only runs on actual Layer-1 entry).

## H4 (P1) — Lane-offset polyline, settings-gated OFF (`BuildPathPolylineRaw` SOURCE-2 ~:19297)

- `MapDb.cs`: add `WalkAlongDirection(startIdx, forward, maxHops, outFwdLanes, outBwdLanes)`
  overload (track `bestJ` in the existing loop; existing 3-arg overload delegates with nulls).
- Per static-graph segment compute right-perpendicular offset from the chosen link's fwd/bwd lane
  counts: `bwd>0` (two-way; node line = divider) → `off = laneWidth*(0.5+laneIdx)` with laneIdx
  snapped from the player's current lateral + `LANE_CHANGE_HYSTERESIS_M` hysteresis via
  `lastLaneIndex` (the deleted LaneCenterFromNode recipe — pointer comment at ~:11000);
  `bwd==0` (one-way; node line = center) → snap to nearest lane center `((i+0.5)-fwd*0.5)*laneWidth`.
  `laneWidth` from `NodeGraph.GetFlags & Freeway ? LANE_WIDTH_HIGHWAY : LANE_WIDTH_SURFACE`.
  Clamp `|off| <= POLY_OFFSET_MAX_M=5.5`. GPS/native segments: offset 0 (log-only calibration).
- Store per-vertex offsets (`pathPolyOffsets`, mirrored in `StabilizePolyline`'s save/revert with
  `prevPathPolyOffsets`); after stabilization build `steerPolyline` = polyline + rightPerp*offset
  with a taper to 0 within `POLY_OFFSET_BLEND_M=10` of sharp vertices (>`POLY_OFFSET_SHARP_DEG=25`)
  to prevent junction corner-cutting.
- `ComputeStanleySteer` consumes `steerPolyline` when valid (same count ⇒ `lastClosestPolySeg`
  stays index-compatible); corridor filter (`DistanceToPolyline2D`) and `ComputeCurveBrake` keep
  the RAW polyline.
- New settings key `laneOffsetPolyline` (default 0/OFF; add to `ids` ~:7952 + `idToName` ~:13210,
  label "Drive assist lane offset (experimental)"). Throttled `EVENT poly-offset: src= fwd= bwd=
  laneW= laneIdx= off= applied=` logged even when OFF (dark-launch calibration).
- Sign self-check: with the setting ON, `poly-lat` mean must move toward ~0 in every environment;
  if it grows, the perpendicular sign is flipped — abort/flag. Re-check `NPC_PATH_CORRIDOR_M`
  after enabling (corridor measures from the raw centerline).

## H5 (P0/P1) — Model-true cast + clearance geometry

- **Rear veto fix (P0, safety):** the reverse rear-clear check and the rear/behind cast must be
  bumper-relative. In the nav-scan behind-cast and the reverse-veto consumers, offset the cast
  origin to the rear bumper: `rearOrigin = playerPos - flatForward * GetVehicleHalfDims(veh).Y`
  (and keep the existing exclude-own-vehicle). Alternatively (smaller diff, same effect): keep
  origins but make the threshold dimension-aware — `REVERSE_REAR_MIN_CLEAR + halfLen` wherever
  `navAssistDistBehind` is compared for reverse decisions (~ApplyCachedSteeringInputs reverse
  block and A7-style consumers). Pick ONE approach; prefer the threshold form for the hotfix.
- **Forward origin (P1):** drive-assist forward casts (5-ray fan, capsule, static-wall — shared
  `startPos` in ProcessSteeringAssist ~:10696) move to just inside the front bumper:
  `startPos = playerPos + flatForward * (halfLen * 0.85f) + (0,0,zLift)`. Own vehicle is already
  excluded from every cast so self-hits cannot occur; distances become bumper-true, which also
  makes `BRAKE_MIN_USEFUL_DIST`/`MIN_BRAKE_DISTANCE` semantics honest. Re-check the two
  constants after the shift (they were tuned center-relative; subtract ~halfLen mentally —
  verify in the next log rather than retuning blind).
- **Height-aware Z (P2):** replace the fixed `+0.5` with `clamp(halfDims.Z * 0.6, 0.4, 1.0)` at
  the drive-assist cast origin (keeps the G5 bottom-clearance lift formula, which is
  radius-relative and unaffected).
- **Bumper-true gap telemetry (log-only this iteration):** append `gapBumper=` (center gap −
  own halfLen − threat half-size when entity) to the apply-assist EVENT next to aReq=, so the
  C1 arbiter switch later uses honest gaps. No control change yet.
- New EVENTs: none beyond the field; note origin change in the banner list. Risk: shifted
  origins change every tuned distance subtly — this is why forward-origin ships in the same
  iteration as H6 (collision telemetry) so regressions are measurable.
